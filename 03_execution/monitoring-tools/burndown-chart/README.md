# Burndown Chart Template — README

## Overview
A Burndown Chart visualizes how much work remains in a sprint or project phase compared to the ideal rate of completion. It helps teams understand whether they are on track, ahead, or behind schedule — and highlights scope changes, velocity issues, and blockers.

This template includes both **Excel** and **Google Sheets** versions designed for daily updates, clear visibility, and AI‑ready analysis.

## How to Use This Template

### 1. Set Your Sprint or Timeframe
Define:
- Sprint length (e.g., 10 days, 2 weeks)  
- Total work (story points, hours, tasks, or units)  

The template will automatically generate the **ideal burndown line**.

### 2. Log Daily Remaining Work
Each day, update:
- Remaining work  
- Completed work  
- Notes on blockers or scope changes  

The chart will update automatically.

### 3. Track Velocity
Velocity is calculated based on:
- Work completed per day  
- Average completion rate  
- Trend compared to ideal line  

Velocity helps predict whether the team will finish on time.

### 4. Document Scope Changes
If work is added or removed mid‑sprint:
- Log the change  
- Add a note  
- The chart will show a visible jump or dip  

This prevents misinterpreting the chart as “falling behind.”

### 5. Share With Stakeholders
Burndown charts are great for:
- Daily standups  
- Sprint reviews  
- Mid‑sprint adjustments  
- AI‑driven forecasting  

Export as PDF, PNG, or share via Google Sheets.

## Best Practices

### Update Daily — Not Weekly
Burndown charts lose value if updated infrequently.  
Daily updates ensure accuracy and help catch issues early.

### Track Scope Changes Explicitly
A burndown chart without scope change notes is misleading.  
Always document added or removed work.

### Use Story Points or Consistent Units
Mixing hours, tasks, and points creates confusion.  
Choose one unit and stick to it for the entire sprint.

### Look for Trends, Not Just Dips
A single bad day is normal.  
A downward trend in velocity is a signal to investigate.

### Use the Chart to Drive Conversations
Burndown charts are not just visuals — they’re prompts for:
- Identifying blockers  
- Adjusting priorities  
- Rebalancing workload  
- Re‑estimating remaining work

## Burndown Interpretation Checklist
Use this checklist to interpret your burndown chart accurately:

- **Is the actual line consistently above the ideal line?**  
  The team may be behind or facing blockers.

- **Is the actual line below the ideal line?**  
  The team may be ahead — or under‑estimating work.

- **Are there sudden jumps upward?**  
  Scope was added.

- **Are there flat periods?**  
  Work stalled; investigate blockers.

- **Is velocity stable or fluctuating heavily?**  
  Fluctuations may indicate unclear requirements or inconsistent estimation.

- **Does the chart reflect reality?**  
  If not, update remaining work more honestly.

## Common Pitfalls to Avoid

### Treating Burndown Charts as Performance Metrics
Burndown charts measure **work**, not **team quality**.  
Never use them to judge individuals.

### Ignoring Scope Changes
If scope changes aren’t logged, the chart becomes meaningless.  
Always annotate changes.

### Over‑Optimistic Remaining Work Estimates
Teams often under‑report remaining work to “look good.”  
This creates misleading charts and bad forecasts.

### Using Burndown Charts for Waterfall Projects
Burndown charts are designed for iterative work.  
For waterfall, use Gantt charts instead.

### Not Accounting for Non‑Working Days
Weekends, holidays, and team PTO affect velocity.  
Adjust the ideal line accordingly.
